Unit 1 • Internet & Web Foundations

1. How the Internet works

What is the Internet?

The Internet is a worldwide network of interconnected computer networks. Devices communicate over it using agreed rules called protocols. It carries many kinds of services, including the World Wide Web, email, file transfer and online calls.

Internet vs World Wide Web

InternetWorld Wide Web (WWW)
The global network infrastructure connecting devices and networks.A service that uses the Internet to access linked pages and resources through browsers.
Supports web, email, messaging, file transfer and more.Uses web technologies such as URLs, HTTP/HTTPS and HTML.

Clients and servers

A client is a device or application that requests a resource or service. A server is a computer or software that receives requests and provides resources or services.

Client
Browser / user device
Request →
Server
Website / application
← Response

Example: When a student opens a college website, the browser (client) requests the page. The web server processes the request and sends back files such as HTML, CSS, JavaScript and images. The browser displays the page.

Basic request–response sequence

  1. The user enters a URL or clicks a link.
  2. The browser identifies the server using the domain name and DNS.
  3. The browser establishes a network connection with the server.
  4. The browser sends an HTTP request.
  5. The server processes the request and returns an HTTP response.
  6. The browser interprets the response and renders the page. It may request additional files such as stylesheets, scripts and images.
Remember: The browser is usually the client. The website's hosting computer or service runs the server software.

2. IP addresses and DNS

IP address

An IP (Internet Protocol) address is a numerical address used to identify a device or network interface so that data can be routed to the correct destination.

TypeFormatExample
IPv4Four decimal numbers separated by dots; each number ranges from 0 to 255.192.168.1.10
IPv6Longer hexadecimal address separated by colons; designed to provide a much larger address space.2001:db8::8a2e:370:7334

A public IP address is generally reachable across the Internet, subject to network and security controls. A private IP address is used inside a local network and is not directly routed across the public Internet.

Domain name

A domain name is a human-readable name used to locate an Internet resource, such as example.com. It is easier to remember than a numerical IP address.

DNS (Domain Name System)

DNS is a distributed naming system that translates domain names into information needed to locate Internet services, commonly IP addresses.

Browser asks for
www.example.com
→
DNS resolver
looks up the name
→
IP address
returned
  1. You enter a domain name in the browser.
  2. The device checks available local and cached DNS information.
  3. If needed, a DNS resolver finds the required DNS record by querying the DNS system.
  4. The resolver returns the result to the device.
  5. The browser can now connect to the server at the resolved address.
Key distinction: DNS finds the address associated with a domain name. HTTP/HTTPS is then used to communicate with the web server.

3. HTTP, HTTPS and status codes

HTTP

HTTP (Hypertext Transfer Protocol) is an application-layer protocol used for communication between web clients and servers. It follows a request–response model.

HTTPS

HTTPS is HTTP protected by encryption using TLS (Transport Layer Security). It helps provide confidentiality, integrity and authentication of the server. Look for the padlock or site-information indicator in the browser, but remember that HTTPS alone does not prove a website is honest or safe in every other way.

HTTPHTTPS
Communication is not protected by TLS encryption.Communication is protected by TLS.
URL commonly begins with http://.URL commonly begins with https://.
Does not provide TLS-based confidentiality or server authentication.Helps protect data from being read or altered in transit and authenticates the server through its certificate.

HTTP request

A request is sent by a client to ask a server to perform an action or return a resource. It commonly contains:

  • Method: indicates the intended action, such as GET or POST.
  • URL/path: identifies the resource.
  • Headers: provide additional information, such as accepted formats or authentication details.
  • Body: optional data sent with the request, often used with POST or PUT.

Common HTTP methods

MethodPurposeExample
GETRetrieve a resource.Load a product page.
POSTSubmit data for processing or create a resource.Submit a registration form.
PUTCreate or replace a resource at a known location.Replace a profile record.
PATCHPartially update a resource.Change a profile photo field.
DELETERequest deletion of a resource.Delete a saved item.

HTTP response

The server's response commonly contains a status code, response headers and an optional body. The body may contain HTML, JSON, an image or another resource.

HTTP status code groups

RangeMeaningCommon examples
1xxInformational — request received; processing continues.100 Continue
2xxSuccess — request was successfully received, understood and handled.200 OK, 201 Created, 204 No Content
3xxRedirection — further action is needed, often to another URL.301 Moved Permanently, 302 Found, 304 Not Modified
4xxClient error — request has a problem or cannot be fulfilled.400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found
5xxServer error — server failed to fulfil an apparently valid request.500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable
Exam trap: 401 means authentication is required or has failed; 403 means the server understood the request but refuses access. A 404 means the requested resource was not found.

Complete example

When a browser requests https://shop.example/products, it may send a GET request. The server may respond with 200 OK and HTML. If the product path does not exist, it may respond with 404 Not Found.

4. Browsers and Developer Tools

What is a web browser?

A web browser is application software used to access and display web resources. Examples include Google Chrome, Mozilla Firefox, Microsoft Edge, Safari and Opera.

What does a browser do?

  • Accepts a URL or user action.
  • Uses DNS and network protocols to communicate with servers.
  • Downloads HTML, CSS, JavaScript, images and other resources.
  • Parses HTML to build the DOM (Document Object Model).
  • Processes CSS to calculate styles and layout.
  • Executes JavaScript and renders the page on screen.
  • Provides features such as tabs, history, bookmarks, downloads and privacy controls.

Browser Developer Tools (DevTools)

Developer Tools are built-in browser utilities used to inspect, debug and analyse web pages. In most desktop browsers, press F12 or Ctrl + Shift + I to open them.

PanelWhat it is used for
Elements / InspectorInspect and temporarily edit HTML elements and CSS styles.
ConsoleView JavaScript errors, warnings and messages; run JavaScript commands.
NetworkInspect requests and responses, status codes, resource sizes and loading time.
Sources / DebuggerView source files, set breakpoints and debug JavaScript.
Application / StorageInspect cookies, local storage, session storage and other site data.
PerformanceRecord and investigate page performance.
Practical exam activity: Open a website, inspect a heading in Elements, find a failed request or status code in Network, and check whether any errors appear in Console.

5. Command line basics

The command line interface (CLI) lets a user interact with an operating system by typing commands in a terminal instead of using only graphical controls.

Why use the command line?

  • Navigate folders and manage files.
  • Run development tools and scripts.
  • Use Git commands.
  • Automate repeated tasks.
  • Work efficiently on remote systems.

Common commands

CommandPurposeExample
pwdShow the current directory (Linux/macOS/Git Bash).pwd
lsList files and folders (Linux/macOS/Git Bash).ls
dirList files and folders in Windows Command Prompt.dir
cdChange directory.cd Documents
cd ..Move to the parent directory.cd ..
mkdirCreate a directory.mkdir website
touchCreate an empty file on common Unix-like shells.touch index.html
echoDisplay text or write text using redirection.echo Hello
clearClear the terminal screen (Windows Command Prompt uses cls).clear
code .Open the current folder in Visual Studio Code, if the command is installed.code .
Note: Commands can differ between Windows Command Prompt, PowerShell, Git Bash, Linux and macOS. Learn the commands used in your lab environment.

Example workflow

mkdir my-website
cd my-website
touch index.html
code .

This creates a folder, enters it, creates an HTML file and opens the folder in VS Code if the command is available.

6. Version control with Git and GitHub

Version control

Version control is a system for recording changes to files over time. It helps developers track history, restore earlier versions, collaborate and manage parallel work.

Git vs GitHub

GitGitHub
A distributed version control system installed and used on a computer.An online platform for hosting Git repositories and collaborating on projects.
Tracks file changes, commits and branches.Provides remote repositories, pull requests, issues, reviews and collaboration tools.
Can work locally without an Internet connection for many operations.Online collaboration features require network access.

Important terms

  • Repository (repo): a project folder tracked by Git, including its history.
  • Working directory: the files currently being edited.
  • Staging area: the selected changes prepared for the next commit.
  • Commit: a saved snapshot of staged changes with a message.
  • Branch: an independent line of development.
  • Remote: a version of the repository hosted elsewhere, often on GitHub.
  • Merge: combines changes from one branch into another.
  • Pull request (PR): a GitHub proposal to review and merge changes from one branch or fork into another repository or branch.

Essential commands

git config --global user.email "you@example.com"Set the email recorded in commits.
git initInitialize a new local Git repository in the current folder.
git clone URLCopy an existing remote repository to your computer, including its history.

Understanding init, clone, fork, push and pull

git init

Start tracking a new local project. It creates the repository metadata in the folder.

git clone

Download an existing repository to your computer. It normally configures the original repository as a remote named origin.

Fork

Create your own GitHub-hosted copy of another user's repository under your GitHub account. Fork is a GitHub platform action, not a basic Git command.

git push

Upload your local commits to a remote repository.

git pull

Fetch changes from a remote and integrate them into your current local branch.

Pull request

Ask repository maintainers to review and merge your proposed changes. It is created on GitHub or a similar hosting platform.

Typical collaboration workflow using a fork

  1. Open the original project on GitHub and click Fork.
  2. Clone your fork to your computer using git clone.
  3. Create a separate branch using git switch -c feature-name.
  4. Edit files and check changes using git status.
  5. Stage and commit changes using git add and git commit.
  6. Push the branch to your fork using git push -u origin feature-name.
  7. Open GitHub and create a pull request from your branch to the original repository.
  8. Respond to review feedback and update the branch if needed.

Example: first local project

mkdir college-site
cd college-site
git init
# Create index.html and add some content
git status
git add index.html
git commit -m "Add home page"
git switch -c about-page
# Create about.html and add content
git add about.html
git commit -m "Add about page"
git switch main
git merge about-page
Common confusion: git add stages changes; it does not upload them. git commit saves them locally; it does not upload them. git push sends commits to a remote repository.
Unit 2 • HTML5

7. HTML5 document structure

What is HTML?

HTML (HyperText Markup Language) is the standard markup language used to describe the structure and meaning of content on web pages. HTML uses elements represented by tags. It is not a programming language.

Basic HTML5 document

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>My First Web Page</title>
</head>
<body>
  <h1>Welcome to My Website</h1>
  <p>This is my first web page.</p>
</body>
</html>

Purpose of important parts

PartPurpose
<!DOCTYPE html>Declares an HTML5 document and helps the browser render in standards mode.
<html>Root element containing the entire HTML document.
lang="en"Identifies the primary language of the page.
<head>Contains metadata and links to resources; its contents are generally not displayed as page content.
<meta charset="UTF-8">Declares the character encoding.
<meta name="viewport">Helps the page adapt to the device's viewport, especially on mobile.
<title>Sets the page title shown in the browser tab and commonly used by search engines.
<body>Contains the visible page content.

Elements, tags and attributes

An element usually consists of an opening tag, content and a closing tag. An attribute provides additional information or configuration.

<a href="https://example.com" target="_blank">Visit Example</a>

Here, <a> is the element tag, href and target are attributes, and “Visit Example” is the link text.

Paired and void elements

Most elements have opening and closing tags, for example <p>Text</p>. Void elements do not wrap content and do not have closing tags, for example <img>, <br>, <hr>, <meta> and <input>.

8. Semantic HTML elements

Semantic HTML means choosing elements according to the meaning and role of the content, rather than only how the content looks.

Important semantic elements

ElementPurposeTypical use
<header>Introductory content for a page or section.Logo, page heading or introductory content.
<nav>A section containing major navigation links.Main menu.
<main>The dominant, unique content of the document.Main article or page content.
<section>A thematic grouping of related content, usually with a heading.Courses section.
<article>Self-contained content that could stand independently.Blog post, news story or forum post.
<aside>Related or supplementary content.Sidebar or related links.
<footer>Footer for a page or section.Copyright or contact information.
<figure>Self-contained media or illustrative content.Image with a caption.
<figcaption>Caption for a figure.Image description or credit.

Example page layout

<body>
  <header>
    <h1>Student Portal</h1>
  </header>
  <nav aria-label="Main navigation">
    <a href="index.html">Home</a>
    <a href="courses.html">Courses</a>
  </nav>
  <main>
    <section>
      <h2>Announcements</h2>
      <article>
        <h3>Exam Schedule</h3>
        <p>The schedule is now available.</p>
      </article>
    </section>
    <aside>Useful student links</aside>
  </main>
  <footer>Copyright 2026</footer>
</body>

Semantic vs non-semantic elements

SemanticNon-semantic / generic
<nav>, <main>, <article>, <footer><div>, <span>
Communicates the meaning or role of content.Does not describe the content's purpose by itself.
Important: Use <div> and <span> when no more meaningful element fits. Do not choose a semantic element merely to get a visual style; use CSS for presentation.

Links — anchor element

Links can point to external pages, pages in the same website, a location within the current page or an email address. Link text should clearly describe the destination or action.

The <img> element embeds an image. It is a void element.

10. HTML tables

HTML tables represent data arranged in rows and columns. They should be used for tabular data, not for general page layout.

Important table elements

ElementPurpose
<table>Creates the table.
<caption>Provides a title or description for the table.
<thead>Groups header rows.
<tbody>Groups the main data rows.
<tfoot>Groups footer rows, such as totals.
<tr>Creates a table row.
<th>Creates a header cell.
<td>Creates a data cell.
<colgroup> / <col>Groups columns so column-level properties can be applied.

Example

<table>
  <caption>Student Marks</caption>
  <thead>
    <tr>
      <th scope="col">Name</th>
      <th scope="col">Subject</th>
      <th scope="col">Marks</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <th scope="row">Aarav</th>
      <td>Web Technology</td>
      <td>85</td>
    </tr>
  </tbody>
</table>

Rowspan and colspan

  • colspan makes a cell span across multiple columns.
  • rowspan makes a cell span across multiple rows.
<td colspan="2">Combined columns</td>
<td rowspan="2">Combined rows</td>

Accessible table headers

Use <th> for header cells. The scope="col" attribute identifies a column header, while scope="row" identifies a row header. A caption helps users understand the table's subject.

11. Forms and input types

What is an HTML form?

A form collects information from users and submits it for processing. Common examples include login, registration, feedback and search forms.

Basic form structure

<form action="/register" method="post">
  <label for="full-name">Full Name</label>
  <input type="text" id="full-name" name="fullName" required>

  <label for="email">Email</label>
  <input type="email" id="email" name="email" required>

  <button type="submit">Register</button>
</form>

Important form attributes and elements

ItemPurpose
<form>Container for form controls.
actionURL where form data is sent.
methodHTTP method used to submit data, commonly GET or POST.
nameName used to identify submitted data. A control generally needs a name to be included in form submission.
idUnique identifier; commonly connects a label to a control.
<label>Provides a text label for a form control.
requiredMakes a control mandatory before submission.
placeholderShows a short hint inside an empty control; it is not a replacement for a label.
valueSpecifies the control's initial or current value.

Common input types

TypePurpose / example
textSingle-line text, such as a name.
emailEmail address; browser can check basic email format.
passwordText entry that masks the characters on screen.
numberNumeric value; may use min, max and step.
telTelephone number; does not automatically enforce a universal phone format.
urlWeb address; browser can check basic URL format.
dateDate picker or date entry.
radioChoose one option from a group sharing the same name.
checkboxChoose one or more independent options.
fileSelect a file for upload.
submitSubmit the form.
resetReset controls to their initial values.
hiddenSubmit a value that is not displayed as a normal control; it is not a security mechanism.
searchEnter a search query.
timeEnter a time.
colorSelect a colour.

Other form controls

  • <textarea>: multi-line text input.
  • <select> and <option>: drop-down list.
  • <button>: clickable button; types include submit, reset and button.
  • <fieldset>: groups related controls.
  • <legend>: caption for a fieldset.

GET vs POST in forms

GETPOST
Form data is commonly appended to the URL as a query string.Form data is sent in the request body.
Useful for searches and requests that retrieve data.Commonly used to submit data that changes server state or contains larger payloads.
Data may appear in browser history, logs and shared URLs.Data is not normally displayed in the URL, but POST alone does not encrypt it; use HTTPS.

HTML validation attributes

  • required: field must be completed.
  • min and max: minimum and maximum for number/date controls.
  • minlength and maxlength: minimum and maximum text length.
  • pattern: regular expression that the value must match.
  • step: allowed step interval for numeric/date-time values.
  • multiple: allows multiple values for supported controls, such as file and email.
Remember: Client-side validation improves usability but can be bypassed. Important data must also be validated on the server.

12. Multimedia in HTML5

HTML5 provides native elements for embedding audio and video without requiring a third-party plug-in.

Audio

<audio controls>
  <source src="lesson.mp3" type="audio/mpeg">
  Your browser does not support the audio element.
</audio>

Video

<video controls width="640" poster="preview.jpg">
  <source src="lesson.mp4" type="video/mp4">
  Your browser does not support the video element.
</video>

Common multimedia attributes

AttributePurpose
controlsDisplays browser playback controls.
autoplayRequests automatic playback; browsers often restrict autoplay, especially with sound.
mutedStarts media without sound.
loopRepeats media after it ends.
posterSpecifies a preview image for a video before playback.
preloadHints how much media data the browser should load before playback.

Captions and accessible media

Provide captions for spoken content in videos. The <track> element can attach timed text, such as captions or subtitles.

<video controls>
  <source src="class.mp4" type="video/mp4">
  <track src="captions-en.vtt" kind="captions"
         srclang="en" label="English" default>
</video>
Accessibility tip: Do not rely on audio alone to communicate important information. Provide captions or a transcript where appropriate, and make media controls usable with a keyboard.

13. Metadata and SEO basics

What is metadata?

Metadata is information about a web page that describes the document, rather than being the main visible content. Much of a page's metadata is placed inside the <head> element.

What is SEO?

SEO (Search Engine Optimisation) is the practice of improving a website so that search engines can understand its content and users can discover useful pages through search results. Good SEO also depends on useful content, site quality, performance and accessibility.

Useful metadata and HTML practices

ItemPurposeExample
Page titleDescribes the page; appears in browser tabs and can appear as the search-result title.<title>HTML Notes for Students</title>
Meta descriptionShort summary that may be used as the search-result snippet.<meta name="description" content="Learn HTML basics.">
ViewportHelps the layout use the device viewport correctly.<meta name="viewport" content="width=device-width, initial-scale=1.0">
Character encodingDeclares how characters are encoded.<meta charset="UTF-8">
Heading structureOrganises content into meaningful sections.<h1>HTML Basics</h1>
Image alt textProvides a text alternative and helps describe image content.alt="Students using laptops"
Descriptive linksHelps users and search engines understand link destinations.<a href="fees.html">View course fees</a>

Example head section

<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>HTML5 Study Notes | Student Portal</title>
  <meta name="description"
        content="Exam notes on HTML5, forms, tables and accessibility.">
</head>

Basic good practices

  • Write a unique, meaningful title for each important page.
  • Use headings in a logical hierarchy.
  • Write useful, original content for people.
  • Use descriptive URLs and meaningful link text.
  • Add appropriate alt text to informative images.
  • Make pages mobile-friendly, fast and easy to navigate.
  • Use semantic HTML and ensure important content is accessible.
Important: A meta description can influence the snippet shown in search results, but search engines may choose a different snippet. Adding a keyword repeatedly does not guarantee a higher ranking.

14. Web accessibility, ARIA and alt text

What is web accessibility?

Web accessibility means designing and developing websites so that people with different abilities can perceive, understand, navigate and interact with them. Accessibility benefits users with permanent, temporary or situational limitations.

Why is accessibility important?

  • Allows more people to use websites independently.
  • Supports keyboard users and people using assistive technologies such as screen readers.
  • Improves clarity, navigation and overall usability.
  • Helps make digital information more inclusive.

WCAG principles — POUR

PrincipleMeaningExample
PerceivableInformation and interface components must be presented in ways users can perceive.Provide text alternatives for meaningful images and captions for videos.
OperableInterface components and navigation must be usable.All functionality should be available using a keyboard.
UnderstandableInformation and operation of the interface must be understandable.Use clear instructions and identify form errors.
RobustContent should work reliably with browsers and assistive technologies.Use valid, semantic HTML and appropriate accessible names and roles.

Alt text

The alt attribute on an image provides a text alternative. Screen readers can announce this text instead of the image.

Image situationWhat to doExample
Informative imageDescribe the information the image communicates.alt="Solar panels installed on a school rooftop"
Functional image used as a link or buttonDescribe the action or destination.alt="Open student dashboard"
Decorative imageUse empty alt text so assistive technology can ignore it.alt=""
Complex chart or diagramProvide a concise alt text and a fuller explanation in nearby text or a linked description.alt="Bar chart comparing annual enrolment"
Do not: use file names such as IMG_1234.jpg as alt text, or repeat “image of” unnecessarily. Do not leave alt text out when an informative image needs a text alternative.

ARIA fundamentals

ARIA (Accessible Rich Internet Applications) is a set of attributes that can add accessibility information such as roles, names, states and properties to web interfaces. ARIA can help assistive technologies understand custom interface components.

Common ARIA attributes

AttributePurposeExample
aria-labelProvides an accessible name when visible text does not provide a suitable name.<button aria-label="Close menu">×</button>
aria-labelledbyUses the text of another element as the accessible name.aria-labelledby="search-title"
aria-describedbyAssociates extra descriptive text with a control.aria-describedby="password-help"
aria-hiddenHides content from the accessibility tree when appropriate.aria-hidden="true"
aria-expandedCommunicates whether a control's expandable content is open or closed.aria-expanded="false"
aria-controlsIdentifies the element controlled by the current element.aria-controls="menu-panel"

Example: accessible search form

<form role="search" action="/search">
  <label for="site-search">Search this website</label>
  <input type="search" id="site-search" name="q">
  <button type="submit">Search</button>
</form>

Native HTML first — ARIA second

Use a native HTML element whenever it provides the required behaviour. For example, use <button> for an action and <a> for navigation. Do not turn a generic <div> into a button with ARIA alone: ARIA does not automatically add keyboard interaction, focus behaviour or built-in functionality.

Golden rule: “No ARIA is better than bad ARIA.” Prefer semantic HTML, add ARIA only when it communicates something native HTML does not already provide, and test with a keyboard and assistive technology.

Other practical accessibility checks

  • Every form field has a clear, associated label.
  • All interactive controls can be reached and used with a keyboard.
  • Focus is visible when navigating with a keyboard.
  • Text has sufficient contrast against its background.
  • Headings follow a meaningful order.
  • Links and buttons have clear names.
  • Errors are explained in text, not only by colour.
  • Videos have captions when they contain speech or meaningful audio.

Practice questions

1. What is the main role of DNS?

DNS looks up information associated with a domain name, commonly resolving it to an IP address so the client can locate the server.

2. Which HTTP status code usually means that a page was not found?

404 Not Found. It is a client-error (4xx) status code.

3. What is the difference between git add and git commit?

git add stages selected changes. git commit records the staged changes in the local repository's history.

4. Is a fork the same as git clone?

No. A fork creates a hosted copy under your GitHub account. Clone copies a repository to your local computer.

5. Which element contains the visible content of an HTML page?

The <body> element.

6. Which semantic element should contain the page's main unique content?

The <main> element.

7. What is the purpose of the name attribute in a form control?

It provides the field name used when the control's value is included in submitted form data.

8. Which input type is suitable for an email address?

type="email". It provides browser-level basic email-format validation.

9. What does alt="" mean for an image?

The image is treated as decorative and can be skipped by assistive technologies.

10. A site works with a mouse but its menu cannot be used with a keyboard. Which WCAG principle is affected?

Operable. Users must be able to operate interface components using available input methods, including a keyboard.
